# Husk OS Live Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline. Continue the current checkout. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver branded, modular Husk Desktop sources and a verifiable live-ISO/VM workflow.
**Architecture:** Preserve the existing GTK/labwc shell and internal identifiers; split pane/launcher composition, centralize identity/layout, validate the releng-derived live profile and prepare safe guest acceptance tooling.
**Tech Stack:** Python, GTK3, gtk-layer-shell, labwc, Archiso, signed pacman packages, Calamares 3.3.14, QEMU and VirtualBox.
**Spec:** docs/superpowers/specs/2026-10-14-husk-live-design.md

## Global Constraints

- Continue branch `mvp` from `0742805`; preserve all earlier tests/features.
- Visible names: `Husk OS`, `Husk Desktop`; technical identifiers remain compatible.
- No changes to the user's physical OS, programs or partitions; no push/publication.
- Preserve package signatures, safe updates, allowlists and installer target guards.
- Windows-like appearance is an MVP stage, not the final design direction.
- Never claim ISO/GUI/VM/game acceptance without running the corresponding test.

## Review Focus

- Malformed custom CSS must leave the default style usable.
- Panel relocation must move launcher/notifications and retain existing shortcuts.
- SDDM must not start a live session before its live user/keyring setup finishes.
- Actual releng boot templates and networking symlinks must survive safely.
- VM preparation must reject existing/hostile disks, raw devices and pre-existing VM targets.
